## Общее для скиллов

### `blocked by policy` на любой команде, даже на чтении файла
- **Причина:** в `~/.codex/config.toml` стоит `[windows] sandbox = "elevated"`. Этот бэкенд песочницы Windows блокирует
  любой подпроцесс. `--sandbox read-only` тут ни при чём.
- **Что делать:** передавать `-c 'windows.sandbox="unelevated"'`. Оба раннера репозитория делают это сами.
  Запрет записи у `read-only` при этом сохраняется.

### Кириллица превращается в мусор
- **В промте:** промт передан аргументом командной строки. Передавайте его **файлом** (раннеры читают файл и подают в stdin как UTF-8).
- **В `.ps1`:** Windows PowerShell 5.1 читает скрипт без BOM как ANSI. Все `.ps1` — UTF-8 **с BOM**.
- **В файлах, которые читает Codex** (`context.md`, `_prompt.txt`, промт тестирования): Codex читает их через `Get-Content`
  Windows PowerShell. Сохраняйте в UTF-8 **с BOM**, иначе модель видит мусор вместо кириллицы.
- **В имени рабочего каталога:** кириллица в имени самого рабочего каталога мешает Codex читать файлы при ревью — используйте ASCII-имя. Кириллица выше по пути (`C:\Users\<Имя>\…`) не мешает.

### `NativeCommandError` при запуске раннера
- **Причина:** в Windows PowerShell вывод раннера перенаправлен через `2>&1`. Codex пишет служебные строки в stderr,
  а PowerShell 5.1 превращает каждую такую строку в ошибку, и при `$ErrorActionPreference='Stop'` скрипт падает.
- **Что делать:** не использовать `2>&1`. Если нужен лог — `powershell -File <раннер> ... *> run.log`.

### `codex.exe не найден`
- **Причина:** десктопное приложение Codex кладёт CLI в `%LOCALAPPDATA%\OpenAI\Codex\bin\<хеш>\codex.exe`,
  и хеш меняется при каждом обновлении.
- **Что делать:** раннеры берут самую свежую сборку из этого каталога, а если её нет — `codex` из `PATH`.
  Хардкодить путь с хешем нельзя.

### `usage limit` сразу после старта
- **Причина:** исчерпан лимит аккаунта Codex/ChatGPT. Прогон заканчивается за несколько секунд с `exit=1`.
- **Что делать:** в сообщении указано время сброса лимита — запустить после него. Подготовленные материалы
  (рабочий каталог, промт) переделывать не нужно.

## codex-test-1c: тестирование через 1c-testpilot

### `MCP tool call requires approval, but approval policy is never`
- **Причина:** в `codex exec` с `approval_policy=never` любой вызов MCP без явного одобрения отклоняется.
- **Что делать:** `-c mcp_servers.1c-testpilot.default_tools_approval_mode="approve"` (раннер ставит сам).
  `--dangerously-bypass-approvals-and-sandbox` не использовать.

### `Error loading config.toml: invalid transport in mcp_servers.1c-testpilot` / `PREFLIGHT FAIL` в `status.txt`
- **Причина:** секция `[mcp_servers.1c-testpilot]` пропала из `~/.codex/config.toml` — обновление или синхронизация
  Codex переписали файл из старого снимка. Флаг `default_tools_approval_mode` при этом создаёт секцию без `command`,
  отсюда «invalid transport».
- **Что делать:** вернуть секцию по [`codex/config.toml.example`](codex/config.toml.example). Раннер проверяет её
  перед запуском (`codex mcp list`). Подключать сервер только флагами `-c mcp_servers.1c-testpilot.command=...`
  не годится: короткий пробник проходит, а в длинном прогоне инструмента нет.
- **Профилактика:** раннер явно задаёт `CODEX_HOME`, чтобы разные запуски не брали разные конфиги; не использовать
  инструменты, которые перезаписывают весь `config.toml` без слияния. Альтернатива — держать сервер в отдельном
  профиле (`testpilot.config.toml`) и запускать с `-p testpilot`.

### `TypeError: tools.mcp__1c_testpilot__tc_session is not a function` / `Direct-call slot ... is unavailable`
Две разные причины:

1. **Модель ушла не в тот JS-контекст.** В Codex 0.160 у MCP-инструментов нет прямого слота: вызов идёт через
   мост exec (code mode) — `tools.mcp__1c_testpilot__tc_session({...})` (дефис в имени сервера → `_`).
   Если в промте есть фраза вида «не через JavaScript / node_repl / `tools.*`», модель выбирает `cua_repl`
   (плагин `unified-computer-use@openai-bundled`), а в его JS-контексте реестра MCP нет.
   - **Что делать:** в начале промта прямо назвать рабочий путь (см. [шаблон](examples/prompt-template.md)) и не
     запрещать `tools.*`. Раннер выключает конкурирующий плагин на время запуска:
     `-c 'plugins."unified-computer-use@openai-bundled".enabled=false'`.
   - **Не помогает:** `mcp_servers.node_repl.enabled=false` (это другой сервер) и переименование MCP-сервера
     (меняется только имя в мосте, конфликт остаётся).
   - **Вредно:** `features.code_mode_host=false` — через тот же мост работают `exec_command` и `apply_patch`,
     и отчёт уже не записать («code-mode host is disabled»).
2. **Гонка старта MCP-сервера.** Тот же промт в одном прогоне проходит, в следующем сразу после — нет.
   - **Что делать:** преамбула велит подождать ~20 с и повторить до 3 раз.

Длина промта сама по себе не причина: длинный промт просто чаще содержит запрет `tools.*` и много UI-сценариев,
для которых `cua_repl` выглядит подходящим.

Дополнительно можно сузить набор инструментов сервера:
`enabled_tools = ["tc_session","tc_app","tc_window","tc_form","tc_find","tc_field","tc_table","tc_doc","tc_calendar"]`
в секции сервера. `tc_find` и `tc_form` не убирать: без них агент не найдёт элементы формы (`find_objects`) и не
снимет снимок формы — шаблон промта на них опирается.

### `EXIT 0`, но `TESTPILOT_CALLS 0` (или прогон кончился за 1–2 минуты)
- **Причина:** Codex завершился, не дойдя до 1С (одна из причин выше, лимит, отказ модели).
- **Что делать:** читать `last_message.md` и `stderr.log` (UTF-16: `Get-Content -Encoding Unicode`), а не ждать отчёт.
  Пробный запуск (`-Probe`) проверяет не всё: короткий промт проходит и тогда, когда полный падает. Полезна вторая
  проверка: преамбула + только первый абзац промта («выполни list_profiles и заверши»).

### Окно «Получение лицензии» / «Лицензия не обнаружена»
- **Причина:** `launch_client` вызван без `exe`/`version`, и testpilot запустил платформу из своего `.env`
  (`TC1C_PLATFORM_EXE`), на которую нет лицензии.
- **Что делать:** в промте всегда `launch_client(..., exe="<путь к 1cv8c.exe нужной версии>", version="<версия>")`.
  Преамбула запрещает модели перебирать версии.

### `Различаются версии клиента и сервера (X - Y)`
- **Причина:** версия в `connect` не совпадает с запущенной платформой.
- **Что делать:** брать `version` из ответа `launch_client`; если `launch_client` вернул `connected`, отдельный `connect` не нужен.

### `no active window` сразу после `launch_client`
- **Причина 1:** окно «Доступ к информационной базе» — не передан пользователь. Нужен `launch_client(..., user="<пользователь>")`.
- **Причина 2:** долгая заставка «Загрузка конфигурационной информации» при первом запуске после обновления
  конфигурации/расширения. Преамбула велит проверять каждые ~30 с до 5 минут.

### `cannot enforce split writable root sets`, отказ всех команд
- **Причина:** рабочий каталог задан коротким 8.3-путём (`C:\Users\ABCD~1\...`, так часто выглядит `%TEMP%`).
- **Что делать:** указывать полный путь. Раннер такой путь не примет.
  Не использовать каталог, где лежит чужой `AGENTS.md`: Codex подхватит его инструкции.

### Агент застрял на одном шаге или бросил весь прогон
- **Причина:** в инструкциях Codex нет правила «сколько пытаться», без него модель либо бесконечно повторяет
  шаг, либо прекращает всё.
- **Что делать:** правило трёх попыток задаётся в [преамбуле](skills/codex-test-1c/scripts/preamble.md):
  после третьей неудачи шаг отмечается ⚠️ и прогон идёт дальше.

### Агент отказывается нажимать кнопки в окне внешней интеграции (Документооборот и т. п.)
- **Что делать:** преамбула прямо разрешает закрывать такие окна «Отменой» без ввода учётных данных.
  Если отказ повторяется — это ⚠️ окружения, окно закрывает пользователь.

### Фоновая задача оборвалась на середине прогона
- **Причина:** фоновые команды инструментов агента обычно ограничены ~10 минутами, а прогон идёт 20–60.
- **Что делать:** запускать раннер отдельным процессом (`Start-Process ... -PassThru`) и ждать `EXIT` в `status.txt`.
  Увидев «процесс исчез», перечитать `status.txt`: процесс пишет `EXIT` и сразу завершается.

### Сценарий не прошёл из-за данных в базе
- **Симптом:** пустая форма выбора, нет нужного справочника или документа, нужная команда отсутствует в списке.
- **Что делать:** это ⚠️, а не дефект кода. В промте заранее описывать обход: копирование существующих документов,
  разрешённая подготовка тестовых данных. Отчёт должен перечислять, какие тестовые данные агент создал или изменил.

### MCP-сервер у Claude не стартует: «Отказано в доступе» / `CONNECTION_CLOSED`
- **Причина:** в `.mcp.json` путь к `1c-testpilot.exe` записан с именем конкретной учётки Windows
  (`C:\Users\<Имя>\...`), а проект открыт под другой учёткой — к чужому профилю нет доступа.
- **Что делать:** писать путь через `${USERPROFILE}` (см. [`claude/mcp.json.example`](claude/mcp.json.example)).
  Если не помогло — проверить, из какого файла взято определение сервера: `.mcp.json` в родительских каталогах
  проекта перекрывает пользовательские настройки.

### Длинный прогон силами самого Claude рвётся (`Connection closed`)
- **Причина:** stdio-соединение MCP `1c-testpilot` у Claude на длинных прогонах нестабильно.
- **Что делать:** длинные прогоны отдавать Codex по схеме `codex-test-1c`; Claude — для коротких точечных проверок.

## Особенности 1c-testpilot при работе с формами 1С

Эти правила стоит включать в каждый промт тестирования (они есть в [шаблоне](examples/prompt-template.md)):

| Ситуация | Как делать |
|---|---|
| Поле-перечисление | `choose_from_drop_list` / `select_option` могут не работать — вводить `input_text` с текстом представления значения |
| Ссылочное поле | выбирать через `start_choosing` + `choose_row`: после `input_text` значение может остаться `committed=false`, и `ПриИзменении` не вызовется |
| Видимость кнопки | `read_fields` не принимает кнопки — проверять через `is_visible` |
| «Только просмотр» | у поля — `is_readonly` плюс попытка ввода; режим «только просмотр» всей формы через `is_readonly` поля не виден |
| Таймаут диагностики | `disconnect` → `connect`; после переподключения ссылки (`ref`) элементов искать заново. Действие, отправленное перед таймаутом, могло не выполниться — проверить результат (например, «*» в заголовке окна) и повторить |
| Найти строку таблицы | `tc_table(action="goto_row", fields={"<заголовок колонки>": "<значение>"})` — ключ это **видимый заголовок колонки** (как в `available_columns`), а не имя элемента. `find_rows(conditions=[...])` только проверяет наличие строки, курсор не ставит |
| Открыть строку списка | `change_row` может вернуть `edit_state_unavailable`, хотя карточка открылась, — проверить `tc_app(action="get_active_window")` |
| «Непредвиденная ошибка» | команда вернула `navigation_failed` / окно `ErrorWindow`: сначала `tc_app(action="get_current_error")` — текст и стек вызовов в `details`, перенести в отчёт, затем закрыть кнопкой `OK` |
| Свойство формы со значением по умолчанию | платформа не пишет его в выгрузку (например, `AutoInsertNewRow=false`) — отсутствие в XML не значит, что правка не применилась |
| Интерфейс на другом языке | названия полей искать по синонимам из таблицы в промте или вернуть язык в карточке пользователя. Язык конфигурации задаётся только в карточке пользователя ИБ и применяется после перезапуска клиента; параметр запуска `/L` (`extra_args`) меняет лишь язык самой платформы |
| Окно выбора файла Windows | может не управляться — не повторять больше трёх раз, отметить ⚠️, загрузку проверить вручную |

## codex-review-1c: код-ревью

### Ревью «ни о чём» — весь файл помечен изменённым
- **Причина:** дифф снят без нормализации окончаний строк: выгрузка 1С хранится в CRLF, а копии — в LF или смешанно.
- **Что делать:** перед диффом приводить оба файла к LF (см. Шаг 2 в [SKILL.md](skills/codex-review-1c/SKILL.md), режим offline).

### `git diff --no-index` вернул код 1 и предупреждения `LF will be replaced by CRLF`
- **Причина:** так `git diff` сообщает, что **различия есть** (0 — одинаковы, больше 1 — настоящая ошибка);
  предупреждения про окончания строк идут в stderr и на дифф не влияют.
- **Что делать:** ничего, проверить, что `diff_*.txt` не пустой. Не запускать построение диффа под
  `$ErrorActionPreference='Stop'` с перехватом stderr — PowerShell 5.1 примет предупреждения за ошибку.

### Codex ревьюит весь модуль, а не правку
- **Причина:** передан только изменённый файл без диффа, и не указаны маркеры правок.
- **Что делать:** класть рядом `diff_*.txt` и в промте назвать формат маркеров авторских правок.

### Находки общие и бесполезные
- **Причина:** в `context.md` не описана механика вокруг правки.
- **Что делать:** включать затронутые объекты (с составом реквизитов и измерений), порядок вызовов, уже известные
  подводные камни, что и зачем изменено (включая неудачные редакции), фактические цифры из данных.
  Чем конкретнее пункт «Логика» в промте (названы сценарии, а не «проверь логику»), тем полезнее результат.

### `MethodInvocationNotSupportedInConstrainedLanguage` в логе
- **Причина:** PowerShell внутри песочницы Codex работает в Constrained Language Mode.
- **Что делать:** ничего — Codex сам переходит на простые команды и доводит ревью до конца.

### Codex зависает или ловит HTTP 503 от MCP-сервера
- **Причина:** при ревью подхватился пользовательский конфиг с MCP-серверами (например, односессионный сервер EDT).
- **Что делать:** раннер ревью всегда запускает с `--ignore-user-config` (на авторизацию это не влияет), поэтому
  модель задаётся параметром `-Model`.

### Codex «висит» без вывода на «Reading additional input from stdin...»
- **Причина:** промпт передан аргументом, а stdin процесса не закрыт: Codex ждёт продолжения ввода и не отвечает никогда
  (внешний таймаут не помогает, если процесс не добит). Особенно часто — на длинных многострочных промптах.
- **Что делать:** промпт только файлом; раннер подаёт его в stdin и закрывает поток. Если запускаете `codex exec` вручную
  из bash — добавляйте `< /dev/null` к вызову с промптом-аргументом.

### Ревью оборвалось: Codex успел только прочитать файлы
- **Причина:** мал таймаут. На объекте с большим модулем (1000+ строк) ревью на `high` идёт 5–15 минут, на `max` — до 25; 300 с не хватает.
- **Что делать:** оставить `-TimeoutSec 1800` (по умолчанию; на уровне `max` меньше не ставить) и запускать раннер в фоне — потолок foreground-вызова
  инструмента в Claude Code короче. В промпте запрещать читать целиком `*.mxlx` / `*.dcs`, если вопрос не о макете.

### Код возврата 0, а ответа нет
- **Причина:** Codex не ответил вообще — исчерпан лимит использования («You've hit your usage limit … try again at …»),
  «at capacity» или слетела авторизация. Файл `-o` при этом не создаётся.
- **Что делать:** раннер считает пустой ответ ошибкой и печатает хвост `_codex_stderr.log` — там время, когда лимит снимется.
  Не выдавать пустоту за «замечаний нет»; повторить позже.

### Отключили все MCP через `-c 'mcp_servers={}'` — Codex не читает файлы и не завершается
- **Причина:** в таблице `mcp_servers` пользовательского конфига может быть внутренний сервер, через который Codex исполняет
  свои shell- и файловые инструменты (например `node_repl`). Обнулив таблицу целиком, гасите и его: «host exited during
  handshake», процесс зависает на выходе, ответ не пишется.
- **Что делать:** использовать `--ignore-user-config` (так делает раннер) или отключать лишние серверы поимённо:
  `-c 'mcp_servers.<имя>={}'`.

### edt: ревью «не того» объекта
- **Причина:** передано голое имя объекта, которое есть и в основной конфигурации, и в расширении (или во внешних
  отчётах) — резолвер возвращает все варианты.
- **Что делать:** указывать путь с именем проекта (`МойПроект→Документы→X`) или выбрать вариант явно.

### Файлы проекта испорчены после правок (CRLF → LF)
- **Причина:** `awk`/`sed` в Git Bash при перезаписи теряют `\r`.
- **Что делать:** править файлы 1С инструментами, сохраняющими окончания строк, и проверять: число `\r` должно
  равняться числу `\n`. Файлы выгрузки 1С — UTF-8 с BOM и CRLF; `Template.xml` макетов — без финального перевода строки.

## Как отличать дефект от ложного срабатывания

Находки Codex — гипотезы. Перед правкой каждую проверить:

1. **По фактам:** метаданные, соседний код, исходники БСП/типовой конфигурации, реальные данные.
   Пример: «ОбработкаОповещения теряет параметры `Параметр` и `Источник`» снимается проверкой сигнатуры БСП —
   `РаботаСФайламиКлиент.ОбработкаОповещения(Форма, ИмяСобытия)` принимает ровно два параметра.
   Другой пример: «может удалить данные другой организации» снимается, если в регистре нет измерения организации.
2. **По замыслу:** искать рядом авторские комментарии — они часто объясняют, почему сделано именно так.
   Совпадение с существующим образцом в проекте — тоже аргумент.
3. **На данных, а не рассуждением:** посчитать строки, документы, суммы.
4. **В тестировании:** ⛔ из-за поведения платформы (например, стандартное сообщение «данные ещё не записаны»)
   или из-за данных в базе — не дефект кода.

Докладывать раздельно: подтвердилось / снято фактами (почему) / оставлено осознанно.
Не вносить правки по находкам автоматически: в момент внедрения чинить то, что ломает результат,
а улучшения устойчивости и скорости откладывать.

## Диагностика: где смотреть, что видела модель

| Что | Где |
|---|---|
| Итог прогона тестов | `<WorkDir>\status.txt` (`START` / `EXIT` / `TESTPILOT_CALLS`; `PREFLIGHT FAIL` — только при сбое проверки конфига), `last_message.md` |
| Лог Codex | `<WorkDir>\stderr.log` — UTF-16, читать `Get-Content -Encoding Unicode`; строки `^mcp: 1c-testpilot/` = вызовы testpilot |
| Полная история сессии | `%USERPROFILE%\.codex\sessions\YYYY\MM\DD\rollout-*.jsonl`: `McpToolCall server=1c-testpilot` — успех, `server=cua_repl` — модель ушла не туда |
| Подключён ли сервер | `codex mcp list` / `codex mcp get 1c-testpilot --json` (конфигурация, не гарантия, что инструмент попал в ход модели) |
| Живая диагностика | `codex exec --json ...` |
| Какие инструменты видит модель | в успешном прогоне попросить выполнить в мосте exec: `text(ALL_TOOLS.filter(x => /1c-testpilot\|tc_session/i.test(x.name + " " + x.description)))` (в `cua_repl` `ALL_TOOLS` нет) |
| Ответ ревью | `<workdir>\_review.md`; лог Codex — `_codex_stderr.log`, `_codex_stdout.log` рядом |
