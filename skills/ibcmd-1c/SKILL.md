# /ibcmd-1c — загрузка и выгрузка 1С через ibcmd

`ibcmd` — утилита автономного сервера 1С (`C:\Program Files\1cv8\<версия>\bin\ibcmd.exe`, платформа 8.3.14+).
Работает с базой напрямую, без Конфигуратора и без лицензии на клиент.

Ниже `<SKILL_DIR>` — каталог этого скилла (там лежит `scripts/`). Скрипты сами находят новейший `ibcmd.exe`
(`-Ibcmd` — указать явно), не прячут вывод ibcmd и возвращают код: `0` — успех, `1` — ошибка ibcmd, `2` — ошибка
параметров, `3` — контроль после загрузки не пройден (`-Verify`).

**Версия платформы.** `ibcmd.exe` есть не в каждой установленной платформе (бывает, что в новейшей сборке его нет, а в
соседней есть). Скрипты берут новейший найденный — проверьте, что он той же версии, на которой работает база и клиенты.

## Перед загрузкой — обязательно
1. **Это изменение базы.** Рабочую (продуктивную) базу трогать только по прямой просьбе пользователя в текущем диалоге.
2. **Резервная копия** — `-BackupDir`: перед импортом сохраняется `.cf` (или `.cfe` с `-Extension`). Откат — ниже.
3. **Нет сеансов в базе.** `import` требует монопольной блокировки: закрыть клиенты, Конфигуратор, тест-клиенты;
   веб-публикация (Apache/IIS) тоже держит базу. Проверка: `Get-Process 1cv8,1cv8c,httpd -ErrorAction SilentlyContinue`.
   Чужие сеансы не завершать — сообщить пользователю. `apply` сам сеансы не рвёт (`--session-terminate=disable` по умолчанию).
4. **База не подключена к хранилищу** — иначе «объект … не захвачен в хранилище!».
5. **Выгрузка на диске соответствует базе.** Импорт заменяет объект целиком тем, что лежит в XML: если в базе после
   выгрузки что-то меняли, эти правки пропадут. Быстрая сверка без полной выгрузки — выгрузить нужные объекты
   (`ibcmd-export.ps1 -Objects`, ниже) и сравнить с исходниками. Есть и `ibcmd infobase config export status
   --base=<ConfigDumpInfo.xml исходников>` — изменения конфигурации относительно состояния выгрузки (не проверялось).
6. **Свободное место.** Импорт, `apply` и `config save` большой конфигурации пишут во `%TEMP%`. Мало места на системном
   диске — `-TempDir <каталог на другом диске>`.

## Загрузка: частичный импорт + apply

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<SKILL_DIR>\scripts\ibcmd-load.ps1" `
  -DbPath "C:\Bases\ERP" -User "Администратор" -BaseDir "C:\Bases\ERP_SRC\cf" `
  -Objects "Reports\МойОтчет" -BackupDir "<scratchpad>\bak" -Verify
```

| Параметр | Что это |
|---|---|
| `-DbPath` | каталог файловой базы (для серверной — дописать в скрипт `--db-server`/`--db-name`, см. `ibcmd help infobase`) |
| `-User`, `-Password` | пользователь базы; пусто — без аутентификации (база без пользователей) |
| `-BaseDir` | корень выгрузки: каталог с `Configuration.xml` (основная конфигурация или расширение) |
| `-Objects` | объект **целиком**: `Reports\X` → `Reports\X.xml` + все файлы каталога `Reports\X\` |
| `-Files` | отдельные файлы: `Configuration.xml`, `Subsystems\Y.xml`, `Reports\X\Forms\Ф.xml` … |
| `-Extension` | имя расширения: импорт и `apply` идут в расширение |
| `-BackupDir` | сохранить `.cf`/`.cfe` перед импортом |
| `-Verify` | после импорта, **до `apply`**, сохранить итог (`*_after.cfe`) и сравнить размер с резервной копией; меньше половины — стоп, код 3, команда отката (нужен `-BackupDir`) |
| `-FullImport` | полный импорт каталога расширения вместо частичного — см. «Полный импорт расширения» |
| `-TempDir` | каталог временных файлов ibcmd (`TEMP`/`TMP`) |
| `-NoCheck` | отключить проверку метаданных после импорта — **только с согласия пользователя**, см. ниже |
| `-SkipApply` | только импорт, без `config apply` |
| `-WhatIf` | показать состав файлов и команды, ничего не делать — **начинать с него** |

Состав файлов:
- **Изменённый объект** — `-Objects <Тип>\<Имя>`.
- **Новый объект** (в т.ч. новое заимствование в расширении) — ещё и `Configuration.xml` (`-Files`), иначе
  «нельзя добавлять объекты метаданных без загрузки родительского объекта». То же для новой формы/макета — родительский `<Объект>.xml`.
- **Состав подсистемы** — `-Files Subsystems\<Имя>.xml` (вложенная: `Subsystems\<Родитель>\Subsystems\<Имя>.xml`).
- Основная конфигурация и расширение — **два отдельных запуска**: сначала основная, потом расширение.

После успеха проверить результат: выгрузить изменённые объекты (`-Objects`) и найти правку, затем — в клиенте
(если есть 1c-testpilot — открыть объект только на чтение).

## Полный импорт расширения
Нужен, когда частичный импорт с `Configuration.xml` падает на проверке всего расширения (см. «Подводные камни»):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<SKILL_DIR>\scripts\ibcmd-load.ps1" `
  -DbPath "C:\Bases\ERP" -User "Администратор" -BaseDir "<каталог расширения>" -Extension "МоёРасширение" `
  -FullImport -BackupDir "<scratchpad>\bak"
```

`-FullImport` требует `-BackupDir` и сам включает `-Verify`: **повторный полный импорт может испортить расширение**
(импорт «успешен», а `.cfe` после него в разы меньше, `apply` падает — см. «Подводные камни»). Условия:
- каталог = **свежая выгрузка расширения из этой базы** + только ваши изменённые объекты (и их строки в
  `ConfigDumpInfo.xml`). Рабочие исходники часто отличаются от базы косметикой (порядок событий формы,
  `UseForFoldersAndItems`, `Template.txt`) — полный импорт протащит её в базу;
- после `apply` выгрузить расширение заново и сравнить с каталогом импорта: не должно быть пропавших файлов.

## Выгрузка в XML

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<SKILL_DIR>\scripts\ibcmd-export.ps1" `
  -DbPath "C:\Bases\ERP" -User "Администратор" -OutDir "C:\Bases\ERP_SRC\cf" -Replace
# расширение: -Extension "МоёРасширение" -OutDir "C:\Bases\ERP_SRC\cfe\МоёРасширение"
```

`ibcmd` выгружает **только в пустой каталог** (скрытые `.git`, `.code-index` тоже делают его непустым).
С `-Replace` скрипт выгружает в `<OutDir>.__new`, затем удаляет из `OutDir` всё, кроме записей на точку,
и переносит новое. Без `-Replace` в непустой каталог — отказ. Типовая ЕРП/УХ — ~120 тыс. файлов, 3–5 минут.
Если `OutDir` под git — после выгрузки `git status` покажет всё, что изменилось в базе.

### Отдельные объекты
Посмотреть или сверить несколько объектов быстрее, чем выгружать всё:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<SKILL_DIR>\scripts\ibcmd-export.ps1" `
  -DbPath "C:\Bases\ERP" -User "Администратор" -OutDir "<пустой каталог>" -Objects "Document.ЗаказКлиента,Report.МойОтчет"
```

Скрипт вызывает `ibcmd infobase config export objects --out=<каталог> --recursive --ignore-unresolved-refs <объекты>`.
- Имена — **в единственном числе через точку** (`Document.X`, `Catalog.X`, `Report.X`, `DefinedType.X`, `Language.X`),
  а не как каталоги выгрузки (`Documents\X`).
- `--ignore-unresolved-refs` — без него выгрузка падает на ссылках на объекты не из списка.
- `--recursive` — с дочерними объектами (формы, макеты). Без него макеты отчёта в выгрузку не попадали; что с ним
  макеты выгружаются, пока не проверено — если их нет, выгрузить отдельно `Report.X.Template.<ИмяМакета>`.
- Только в пустой или новый каталог (`-Replace` здесь не работает: заменять полные исходники частью нельзя).

### Все расширения и их список
```powershell
ibcmd infobase config extension list <авторизация>
ibcmd infobase config export all-extensions <авторизация> <пустой каталог>   # по подкаталогу на каждое расширение
```

## Создание базы
```powershell
# из выгрузки данных .dt
ibcmd infobase create --data=<каталог данных> --db-path=<новый каталог> --create-database --restore=<файл.dt>
# из файла конфигурации .cf, сразу с применением
ibcmd infobase create --data=<каталог данных> --db-path=<новый каталог> --create-database --load=<файл.cf> --apply --force
```
- В новой базе **нет пользователей** — дальше все команды без `--user`.
- `--data=` (каталог данных автономного сервера) указывать явно: без него ibcmd берёт
  `%LOCALAPPDATA%\1C\1cv8\standalone-server\` и, по наблюдению, может завести базу там.
- Пустая временная база + `config load --extension=<имя> <файл.cfe>` + `config export --extension=<имя>` — способ получить
  XML из чужого `.cfe`, не трогая рабочую базу. **Выгрузка заимствованных объектов при этом неполная:** без настоящей
  основной конфигурации теряются `CommandSet`/`UseForFoldersAndItems` базовых форм, ссылки на объекты основной
  конфигурации пишутся UUID'ами. Эталон исходников — выгрузка из настоящей базы; если иначе нельзя — выгрузить так же
  предыдущую версию `.cfe` и переносить в исходники только файлы, различающиеся между двумя такими выгрузками.

## Откат
- Импорт упал — база не изменилась (импорт атомарный).
- Импорт прошёл, `apply` ещё нет — `ibcmd infobase config reset <авторизация> [--extension=<имя>]`.
- Уже применено или `-Verify` показал резкое уменьшение — загрузить резервную копию:
  `ibcmd infobase config load <авторизация> [--extension=<имя>] <файл.cf|.cfe>`, затем
  `ibcmd infobase config apply <авторизация> [--extension=<имя>] --force`.

## Подводные камни
- **Справка.** `ibcmd config import --help` печатает только общий список режимов. Полная справка по ключам —
  `ibcmd help config`, `ibcmd help infobase`, `ibcmd help extension`; вывод в cp866. Удобнее сохранить в файл и искать
  по нему: `ibcmd help config | iconv -f cp866 -t utf-8 > ibhelp.txt`. Команды пишутся с префиксом:
  `ibcmd infobase config import files …`.
- **Пароль.** При пустом пароле `--password=` ibcmd всё равно спрашивает его с консоли и без stdin повисает.
  Скрипты подают пароль ещё и в stdin. Руками: `echo "" | ibcmd …` (bash) или `cmd /c "… --password="` с `echo.|`.
- **Команды без `--user` в базе с пользователями** (`config save`, `extension list`) не падают, а **молча висят**,
  ожидая ввода. В такой базе `--user` обязателен; в bash — ещё и `< /dev/null` или `echo "" |`.
- **База без пользователей** (новая, созданная `ibcmd infobase create`): любой `--user` → «Идентификация пользователя
  не выполнена». Запускать без `-User`.
- **Кириллица в аргументах.** Из PowerShell (скрипты скилла) работает. Из Git Bash в одних окружениях работала
  (`--db-path=C:\Bases1C\…\ЕРП`, `--extension=РМП_УХ`, `--name=ТестРасш`), в других — портилась; при странных
  «не найдено» с кириллическими именами — запускать через скрипты. Вывод ibcmd в Git Bash бывает и в cp866
  (`| iconv -f cp866 -t utf-8`), и в UTF-8 — строки `╨Ш╨╝…` после iconv означают, что iconv был лишним, это не ошибка.
- **`.ps1` — UTF-8 с BOM**, иначе Windows PowerShell 5.1 читает кириллицу как ANSI. Массивы через `-File` передавать
  строкой через запятую: `-Files "Configuration.xml,Subsystems\Отчеты.xml"` (скрипт разбирает сам).
- **«Ссылка на неизвестный предопределенный элемент …» при импорте расширения с `Configuration.xml`.**
  С корнем расширения ibcmd проверяет всё расширение и падает на старых ссылках форм (например, на предопределённые
  элементы основной конфигурации), которые в базе давно работают. Импорт одной формы/объекта без `Configuration.xml`
  эту проверку не запускает. Обход — `-FullImport` (раздел «Полный импорт расширения»): полный импорт этой проверки
  не делает и прошёл там, где частичный падал (ЕРП/УХ, 8.3.27). `-NoCheck` — крайний вариант, только после явного
  «да» пользователя: проверка отключается целиком.
- **Повторный полный импорт расширения может его испортить** (8.3.27.2325, расширение ~30 МБ): импорт отработал
  «успешно», но `config save` дал `.cfe` 1,9 МБ вместо 30 МБ, `apply` — «Недопустимое значение аргумента функции»
  (ExtensionsManagerImpl.cpp), Конфигуратор — «Уже существует объект с именем Язык.Русский». Поэтому `-FullImport`
  только с резервной копией и `-Verify`. Откат, который сработал: `config load --extension=<имя> <резервная.cfe>` +
  `apply --force`. Точечную правку в такой ситуации удалось загрузить Конфигуратором:
  `1cv8.exe DESIGNER /F<база> /N"<пользователь>" /LoadConfigFromFiles <каталог> -Extension <имя> -files "<отн.путь>" -Format Hierarchical`,
  затем `/UpdateDBCfg -Extension <имя>`.
- **«Ошибка исключительной блокировки информационной базы»** — в базе есть сеансы (клиент, Конфигуратор,
  веб-публикация, ibcmd в соседнем окне). Встречалось и на `config save` (с `--db` и без), и на `import`: перед
  `-BackupDir`/`-Verify` базу тоже надо освободить.
- **«Идентификатор … загружаемой конфигурации отличается от … сохраненной»** — выгрузка не от этой базы
  (или база пустая, без конфигурации). Частичный импорт возможен только в «свою» базу; в пустую — полный
  `ibcmd infobase config import <авторизация> <каталог>`.
- **Скрипты-скиллы редактирования XML** (`cfe-borrow`, `subsystem-edit` и т.п.) могут переформатировать файл целиком
  (`<Comment/>` → `<Comment />`, версия формата). Для ibcmd это не ошибка, но перед коммитом выгрузки смотреть `git diff`.

## Итог — в память проекта
После загрузки или выгрузки дописать в память проекта (`Memory Bank.md`, `MEMORY.md` или файл из `CLAUDE.md`/`AGENTS.md`):
дату, базу, что загружено (объекты, основная/расширение), путь резервной копии, итог (`apply` прошёл / нет и почему).
Без паролей и сырых логов.
