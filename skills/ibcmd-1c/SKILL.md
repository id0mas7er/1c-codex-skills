# /ibcmd-1c — загрузка и выгрузка 1С через ibcmd

`ibcmd` — утилита автономного сервера 1С (`C:\Program Files\1cv8\<версия>\bin\ibcmd.exe`, платформа 8.3.14+).
Работает с базой напрямую, без Конфигуратора и без лицензии на клиент.

Ниже `<SKILL_DIR>` — каталог этого скилла (там лежит `scripts/`). Скрипты сами находят новейший `ibcmd.exe`
(`-Ibcmd` — указать явно), не прячут вывод ibcmd и возвращают код: `0` — успех, `1` — ошибка ibcmd, `2` — ошибка параметров.

## Перед загрузкой — обязательно
1. **Это изменение базы.** Рабочую (продуктивную) базу трогать только по прямой просьбе пользователя в текущем диалоге.
2. **Резервная копия** — `-BackupDir`: перед импортом сохраняется `.cf` (или `.cfe` с `-Extension`). Откат — ниже.
3. **Нет сеансов в базе.** `import` требует монопольной блокировки: закрыть клиенты, Конфигуратор, тест-клиенты;
   веб-публикация (Apache/IIS) тоже держит базу. Чужие сеансы не завершать — сообщить пользователю.
   `apply` сам сеансы не рвёт (`--session-terminate=disable` по умолчанию).
4. **База не подключена к хранилищу** — иначе «объект … не захвачен в хранилище!».
5. **Выгрузка на диске соответствует базе.** Частичный импорт заменяет объект целиком тем, что лежит в XML:
   если в базе после выгрузки что-то меняли, эти правки пропадут.

## Загрузка: частичный импорт + apply

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<SKILL_DIR>\scripts\ibcmd-load.ps1" `
  -DbPath "C:\Bases\ERP" -User "Администратор" -BaseDir "C:\Bases\ERP_SRC\cf" `
  -Objects "Reports\МойОтчет" -BackupDir "<scratchpad>\bak"
```

| Параметр | Что это |
|---|---|
| `-DbPath` | каталог файловой базы (для серверной — дописать в скрипт `--db-server`/`--db-name`, см. `ibcmd help infobase`) |
| `-User`, `-Password` | пользователь базы; пусто — без аутентификации (база без пользователей) |
| `-BaseDir` | корень выгрузки: каталог с `Configuration.xml` (основная конфигурация или расширение) |
| `-Objects` | объект **целиком**: `Reports\X` → `Reports\X.xml` + все файлы каталога `Reports\X\` |
| `-Files` | отдельные файлы: `Configuration.xml`, `Subsystems\Y.xml`, `Reports\X\Forms\Ф.xml` … |
| `-Extension` | имя расширения: импорт и `apply` идут в расширение |
| `-BackupDir` | сохранить `.cf`/`.cfe` перед импортом |
| `-NoCheck` | отключить проверку метаданных после импорта — **только с согласия пользователя**, см. ниже |
| `-SkipApply` | только импорт, без `config apply` |
| `-WhatIf` | показать состав файлов и команды, ничего не делать — **начинать с него** |

Состав файлов:
- **Изменённый объект** — `-Objects <Тип>\<Имя>`.
- **Новый объект** (в т.ч. новое заимствование в расширении) — ещё и `Configuration.xml` (`-Files`), иначе
  «нельзя добавлять объекты метаданных без загрузки родительского объекта». То же для новой формы/макета — родительский `<Объект>.xml`.
- **Состав подсистемы** — `-Files Subsystems\<Имя>.xml` (вложенная: `Subsystems\<Родитель>\Subsystems\<Имя>.xml`).
- Основная конфигурация и расширение — **два отдельных запуска**: сначала основная, потом расширение.

После успеха проверить результат в клиенте (если есть 1c-testpilot — открыть объект только на чтение).

## Выгрузка в XML

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<SKILL_DIR>\scripts\ibcmd-export.ps1" `
  -DbPath "C:\Bases\ERP" -User "Администратор" -OutDir "C:\Bases\ERP_SRC\cf" -Replace
# расширение: -Extension "МоёРасширение" -OutDir "C:\Bases\ERP_SRC\cfe\МоёРасширение"
```

`ibcmd` выгружает **только в пустой каталог** (скрытые `.git`, `.code-index` тоже делают его непустым).
С `-Replace` скрипт выгружает в `<OutDir>.__new`, затем удаляет из `OutDir` всё, кроме записей на точку,
и переносит новое. Без `-Replace` в непустой каталог — отказ. Типовая ЕРП/УХ — ~120 тыс. файлов, 3–5 минут.
Если `OutDir` под git — после выгрузки `git status` покажет всё, что изменилось в базе.

## Откат
- Импорт упал — база не изменилась (импорт атомарный).
- Импорт прошёл, `apply` ещё нет — `ibcmd infobase config reset <авторизация> [--extension=<имя>]`.
- Уже применено — загрузить резервную копию: `ibcmd infobase config load <авторизация> [--extension=<имя>] <файл.cf|.cfe>`,
  затем `ibcmd infobase config apply <авторизация> [--extension=<имя>] --force`.

## Подводные камни
- **Справка.** `ibcmd config import --help` печатает только общий список режимов. Полная справка по ключам —
  `ibcmd help config` (или `ibcmd help infobase`), вывод в cp866: `| iconv -f cp866 -t utf-8`.
  Команды при этом пишутся с префиксом: `ibcmd infobase config import files …`.
- **Пароль.** При пустом пароле `--password=` ibcmd всё равно спрашивает его с консоли и без stdin повисает.
  Скрипты подают пароль ещё и в stdin. Руками: `echo "" | ibcmd …` (bash) или `cmd /c "… --password="` с `echo.|`.
- **База без пользователей** (новая, созданная `ibcmd infobase create`): любой `--user` → «Идентификация пользователя
  не выполнена». Запускать без `-User`.
- **`.ps1` — UTF-8 с BOM**, иначе Windows PowerShell 5.1 читает кириллицу как ANSI. Массивы через `-File` передавать
  строкой через запятую: `-Files "Configuration.xml,Subsystems\Отчеты.xml"` (скрипт разбирает сам).
- **«Ссылка на неизвестный предопределенный элемент …» при импорте расширения с `Configuration.xml`.**
  С корнем расширения ibcmd проверяет всё расширение, и падает на старых ссылках форм (например, на предопределённые
  элементы основной конфигурации), которые в базе давно работают. Импорт одной формы/объекта без `Configuration.xml`
  эту проверку не запускает. Если ошибки не про загружаемые объекты, обойти можно `-NoCheck` — только после
  явного «да» пользователя: проверка отключается целиком. `apply` всё равно проверяет метаданные.
- **«Ошибка исключительной блокировки информационной базы»** — в базе есть сеансы (клиент, Конфигуратор,
  веб-публикация, ibcmd в соседнем окне). `config save --db` (конфигурация БД) требует монопольного доступа;
  без `--db` сохраняется основная конфигурация — после `apply` они совпадают.
- **«Идентификатор … загружаемой конфигурации отличается от … сохраненной»** — выгрузка не от этой базы
  (или база пустая, без конфигурации). Частичный импорт возможен только в «свою» базу; в пустую — полный
  `ibcmd infobase config import <авторизация> <каталог>`.
- **Скрипты-скиллы редактирования XML** (`cfe-borrow`, `subsystem-edit` и т.п.) могут переформатировать файл целиком
  (`<Comment/>` → `<Comment />`, версия формата). Для ibcmd это не ошибка, но перед коммитом выгрузки смотреть `git diff`.

## Итог — в память проекта
После загрузки или выгрузки дописать в память проекта (`Memory Bank.md`, `MEMORY.md` или файл из `CLAUDE.md`/`AGENTS.md`):
дату, базу, что загружено (объекты, основная/расширение), путь резервной копии, итог (`apply` прошёл / нет и почему).
Без паролей и сырых логов.
